## Контекст

YT Summarizer сейчас — self-hosted инструмент для одного пользователя. Переход в multi-tenant SaaS поднимает ряд технических и продуктовых вопросов. Этот документ фиксирует исследования, инсайты и решения по мере их появления.

## 1. Конкурентный ландшафт

### youtube-transcript.io

**Источник**: прямой анализ сайта, 25.10.2026  
**URL**: https://www.youtube-transcript.io/

**Ключевые наблюдения:**

- 2.6M+ пользователей, 39 000+ отзывов — зрелый продукт с реальной аудиторией
- Модель монетизации: токены (1 токен = 1 транскрипт)
  - Free: 25 токенов/мес
  - Plus: $9.99/мес → 1 000 транскриптов
  - Pro: $24.99/мес → 3 000 транскриптов (до 10 000 за доп. плату)
  - Enterprise: custom
- Фокус продукта: **транскрипт как сырьё**, не как конечный продукт. AI Summary — дополнение, не ядро.
- Аудитория широкая: маркетологи, журналисты, студенты, пасторы — не разработчики
- Есть API доступ (`YouTube Transcript API` раздел на сайте)
- Bulk/Channel обработка — отдельная фича, не основной путь

**Что делает хорошо:**
- Очень низкий порог входа (бесплатно, без регистрации на базовом уровне)
- Скорость ("instantaneous") — кэширование очевидно
- Простота: одно поле, одна кнопка
- Без рекламы (упоминается в отзывах как ключевое преимущество)

**Где наш продукт сильнее (потенциально):**
- Локальная обработка без отправки данных на сервер — конфиденциальность
- Whisper STT для видео без субтитров
- Полноценный pipeline (cleanup → summary → mindmap → chat)
- Главы (chapter-aware formatting)
- Self-hosted опция для enterprise

## 2. Главная техническая проблема: YouTube rate limiting

### Природа ограничений

YouTube ограничивает доступ на нескольких уровнях одновременно:

| Уровень | Триггер | Симптом |
|---------|---------|---------|
| IP-level 429 | Много запросов с одного IP | `HTTP 429 Too Many Requests` |
| Bot detection | Паттерны запросов yt-dlp | Redirect на captcha, пустой ответ |
| Cookie/session expiry | Протухшие куки | `Sign in required` или пустые субтитры |
| Age-restriction | Видео с ограничением | Требует авторизованный аккаунт |
| API quota | YouTube Data API v3 | 10K units/day по умолчанию |

### Куки нужны не всегда

Важное наблюдение: для **публичных видео без возрастных ограничений** куки не нужны вовсе. Большинство контента попадает в эту категорию.

Куки нужны только для:
- Age-restricted видео
- Некоторых видео, помеченных как "sign-in required"
- Ситуации когда YouTube считает IP подозрительным и требует верификацию

**Вывод**: Стратегия "без кук для публичного контента + fallback Whisper STT для остального" покрывает большинство кейсов.

### Три стратегии обхода

**Стратегия 1: Агрессивное кэширование (главный рычаг)**

Для сервисов с большой аудиторией это самое важное решение. Распределение запросов Парето: топ 10K видео дают >80% трафика. Популярные лекции, TED-talks, новости запрашиваются тысячами пользователей.

- TTL кэша: 7–30 дней (субтитры видео не меняются)
- У нас уже реализовано: dedup по `video_id` в архитектуре
- Нужно добавить: expire-стратегия + hit/miss метрики

**Стратегия 2: Лёгкий клиент вместо yt-dlp**

yt-dlp — мощный инструмент, но он делает 3–5 HTTP запросов на одно видео (player page, metadata, subtitle file). Библиотека `youtube-transcript-api` (Python) делает ровно 2: получает `timedtext` URL из player config → скачивает VTT.

- Меньше запросов = медленнее накапливается rate limit на IP
- Меньше заметен для bot-detection (меньше характерных паттернов)
- Минус: теряем поддержку аудио-скачивания для STT pipeline (yt-dlp нужен для audio extraction)

**Решение для нашего случая**: гибрид — `youtube-transcript-api` для субтитров, yt-dlp только для аудио (STT path).

**Стратегия 3: IP rotation**

Для сервисов с нагрузкой >1K запросов/день без кэша — необходимость. Варианты:

| Вариант | Стоимость | Надёжность |
|---------|-----------|------------|
| Datacenter IPs (несколько регионов) | ~$5-10/мес/сервер | Средняя — YouTube детектирует datacenter |
| Residential proxy pool | $5–15/GB трафика | Высокая — выглядит как обычный пользователь |
| Множество мелких VPS в разных AS | $3-5/мес каждый | Хорошая при достаточном количестве |

Траффик для субтитров минимальный: VTT файл ~50KB. 1000 запросов = ~50MB = <$1 на residential proxies.

**На ранней стадии (до 10K DAU)**: достаточно кэша + одного запасного сервера в другом регионе.

**Стратегия 4: Whisper STT как universal fallback**

Если субтитры недоступны по любой причине (ограничения, нет субтитров, 429) — скачать аудио и транскрибировать через Whisper. У нас уже реализован полный STT pipeline (Epic 30–32, 41–43).

Это уникальное преимущество — конкуренты обычно просто возвращают ошибку.

### Рекомендуемая архитектура для multi-tenant

```
User request
     │
     ▼
Rate limiter (per-user tokens/quota)
     │
     ▼
Cache check (video_id в DB?) ──hit──→ Return cached result
     │ miss
     ▼
Request router
     │
     ├──→ youtube-transcript-api (субтитры, лёгкий клиент)
     │         │ fail (429 / no subs)
     │         ▼
     │    yt-dlp audio extraction → Whisper STT
     │
     ▼
Store in shared cache + return
```

## 3. Бизнес-модель: наблюдения

### Токен vs. Подписка

youtube-transcript.io использует **токены** (1 запрос = 1 токен), не просто подписку на время. Это умно:
- Пользователь чувствует ценность каждого токена (не "у меня безлимит, буду мусорить")
- Естественное ограничение нагрузки
- Upsell путь очевиден: кончились токены → купи ещё

**Для нашего продукта**: аналогичная модель работает. Дополнительно можно заряжать больше за LLM-стадии (cleanup/summary стоят реальных вычислений).

### Ценообразование

| Tier | Цена | Транскрипты | Цена за транскрипт |
|------|------|-------------|-------------------|
| Free | $0 | 25/мес | — |
| Plus | $9.99 | 1 000/мес | $0.01 |
| Pro | $24.99 | 3 000/мес | $0.008 |

Себестоимость извлечения субтитров — фактически $0 при кэше. Себестоимость LLM summary — зависит от провайдера (если Ollama self-hosted: стоимость GPU времени).

### Конфиденциальность как дифференциатор

Ни один из анализируемых конкурентов не предлагает self-hosted опцию. Для enterprise-клиентов с требованиями к data residency это может быть решающим аргументом.

## 4. Экономика чата с транскриптом

### Постановка проблемы

Большая лекция — 100K+ символов ≈ 25K токенов. Если каждое сообщение в чате отправляет весь транскрипт как контекст, стоимость на пользователя может превысить доход с плана.

**Расчёт наивного подхода (full context per message):**

| LLM | Цена input | Стоимость 1 сообщения (100K контекст) |
|-----|-----------|---------------------------------------|
| Claude Sonnet | $3/1M токенов | ~$0.09 |
| GPT-4o | $2.5/1M | ~$0.07 |
| Gemini Flash | $0.075/1M | ~$0.002 |
| Mistral 7B (local) | ~$0.005/час GPU | ~$0.01–0.02 |

При плане $10/мес и 200 сообщений/мес на пользователя через облачный LLM → $14–18 себестоимости на одного пользователя. Нежизнеспособно.

---

### Три архитектурных ответа

#### Ответ 1: RAG (главное решение)

Вместо отправки всего транскрипта — умный поиск нужных кусков.

**Схема:**
1. При сохранении транскрипта: делим на чанки по ~500 символов → считаем эмбеддинги каждого чанка
2. При вопросе пользователя: эмбеддинг вопроса → top-5 ближайших чанков (~2.5K символов) → LLM
3. LLM видит: вопрос + 5 релевантных отрывков, не весь текст

**Результат:** 25K → 5K токенов. Стоимость падает **в 5 раз**.

**Что нужно технически:**
- `sentence-transformers` (Python, CPU, ~50ms/чанк)
- SQLite + `sqlite-vec` extension или numpy cosine similarity
- Никаких внешних сервисов

#### Ответ 2: Иерархический контекст

Не все вопросы требуют одинакового контекста:

```
Вопрос
  ↓
Тип вопроса?
  ├─ "О чём вообще видео?" → summary (1K токенов, ~$0.003)
  ├─ "Что говорилось про X?" → RAG retrieval (5K токенов, ~$0.015)
  └─ "Процитируй точно..." → full transcript (25K токенов, ~$0.09)
               ↑ пользователь явно запросил, считается дороже
```

Большинство вопросов — первые два типа.

#### Ответ 3: Локальный LLM на GPU-сервере

Если вместо API использовать собственный GPU-сервер (RunPod, vast.ai):

- A100 на RunPod: ~$1.50/час
- Mistral 7B / Llama 3.1 8B: ~50 токенов/сек
- Сообщение с полным 100K контекстом: ~$0.01–0.02

В 5–10 раз дешевле Claude/GPT API. И это уже наш путь — архитектура совместима с Ollama.

---

### Рабочая схема для плана $10/мес

```
RAG retrieval (CPU, local)         ~$0.001/запрос
+
Gemini Flash / local LLM           ~$0.005–0.015/сообщение
+
Компрессия истории через 10 обменов (сдерживает рост контекста)
─────────────────────────────────────────────────────────────
Итого: ~$0.01–0.02 за сообщение
```

**Медианный пользователь: 50 сообщений/мес → $0.50–1.00 себестоимость.**  
При $10/мес план — комфортная маржа.  
Активный пользователь с 500 сообщений/мес → $5–10 себестоимость — граница рентабельности.

---

### Дополнительные рычаги экономии

**Компрессия истории**: после 8–10 обменов автоматически сжать историю через дешёвый LLM. Иначе контекст растёт с каждым сообщением.

**Prefix caching**: Claude API кэширует повторяющийся prefix (один и тот же транскрипт). Повторные запросы от одного пользователя — дешевле (кэш-хит = 10% цены).

**Лимиты по сессиям**: вместо лимита "N сообщений" — лимит "N сессий чата в месяц". Каждая сессия = отдельная история. Пользователь понимает ценность, нет ощущения "считают нажатия Enter".

**Разные тиры чата**:
- Free: только RAG-based chat (дёшево)
- Paid: full-context chat (дороже, но пользователь платит)

---

### Вывод

При использовании RAG + local LLM (или Gemini Flash) чат с транскриптом экономически жизнеспособен при $10/мес плане для большинства пользователей. Активные пользователи — граница рентабельности; для них имеет смысл явный лимит или тарифный барьер.

**Текущая реализация**: чат уже работает через Ollama (локальный LLM). Для self-hosted и серверного Ollama стоимость на запрос — фактически $0 (только стоимость GPU-времени). RAG — следующий шаг для масштабирования до multi-tenant.

## 5. Открытые вопросы

- [ ] Как обращаться с аккаунтами Google для age-restricted контента? Пул аккаунтов — юридически серая зона (ToS).
- [ ] Нужен ли официальный YouTube Data API v3? Даёт quota на субтитры (50 units/request), но требует Google project + ключи. Рассмотреть как дополнительный fallback.
- [ ] Как считать "токены" для LLM-стадий? 1 токен за субтитры + N токенов за summary отдельно, или единая цена за полный pipeline?
- [ ] Нужна ли регистрация для free tier? youtube-transcript.io работает без неё — это friction reducer. Но без аккаунта нет персональной истории.
